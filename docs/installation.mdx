## 📦 Installation Options

> **Release candidate status:** `3.0.0-rc.3` is the current published candidate on `next`, released through the manual-only Trusted Publisher path. Use `@next` for evaluation and pin `@3.0.0-rc.3` for a reviewed deployment.

**Option 1: Via npm (recommended)** — no installation needed, just use `npx` in your MCP config:

```bash
npx --yes @daxiong888/mcp-jenkins@next
```

**Option 2: Local installation:**

```bash
git clone https://github.com/daxiong888/mcp-jenkins.git
cd mcp-jenkins
npm install
npm run build
```

> **Note:** Keep credentials off the command line entirely. `--api-token` / `--bearer-token` CLI arguments are visible in process lists, and any interactive command carrying a token — including `--env KEY=value` or `VAR=value` prefixes — lands in shell history. Put credentials in your MCP client's `env` config (a local config file — restrict its permissions and never commit it) or inject them from a secret manager. The command-line examples below therefore show only non-secret values.

## 🎯 Claude Code CLI

**For:** Claude AI via command line interface

**Via npm with env vars (recommended):**

```bash
claude mcp add --transport stdio --scope user jenkins \
  --env MCP_JENKINS_URL=https://pipeline.yourcompany.com \
  -- npx --yes @daxiong888/mcp-jenkins@latest
```

**Via npm with a CLI URL arg:**

```bash
claude mcp add --transport stdio --scope user jenkins \
  -- npx --yes @daxiong888/mcp-jenkins@latest \
  --url https://pipeline.yourcompany.com
```

**Local installation:**

```bash
claude mcp add --transport stdio --scope user jenkins \
  --env MCP_JENKINS_URL=https://pipeline.yourcompany.com \
  -- node $HOME/path/to/mcp-jenkins/dist/index.js
```

**Multiple Jenkins instances:**

```bash
claude mcp add --transport stdio --scope user jenkins \
  --env MCP_JENKINS_URL="https://pipeline.yourcompany.com,https://scheduler.yourcompany.com" \
  -- npx --yes @daxiong888/mcp-jenkins@latest
# Instances named "pipeline" and "scheduler" automatically from hostnames
```

These commands carry no credentials: after registering, add `MCP_JENKINS_USER`/`MCP_JENKINS_API_TOKEN` (or `MCP_JENKINS_BEARER_TOKEN`) to the generated client config's `env` block — see the JSON examples below — or inject them from a secret manager.

Verify: `claude mcp list` should show `jenkins`

## 🖥️ Claude Desktop

**For:** Claude AI desktop application

### 1. Open Configuration File

**macOS:**

```bash
open ~/Library/Application\ Support/Claude/claude_desktop_config.json
```

**Windows:**

```bash
notepad %APPDATA%\Claude\claude_desktop_config.json
```

### 2. Add Configuration

**Via npm with env vars (recommended):**

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": ["--yes", "@daxiong888/mcp-jenkins@latest"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com",
        "MCP_JENKINS_USER": "your_username",
        "MCP_JENKINS_API_TOKEN": "your_api_token"
      }
    }
  }
}
```

**Via npm with a CLI URL arg (credentials stay in env):**

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": [
        "--yes",
        "@daxiong888/mcp-jenkins@latest",
        "--url",
        "https://pipeline.yourcompany.com"
      ],
      "env": {
        "MCP_JENKINS_USER": "your_username",
        "MCP_JENKINS_API_TOKEN": "your_api_token"
      }
    }
  }
}
```

**Local installation (credentials stay in env):**

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "node",
      "args": ["/absolute/path/to/mcp-jenkins/dist/index.js"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com",
        "MCP_JENKINS_USER": "your_username",
        "MCP_JENKINS_API_TOKEN": "your_api_token"
      }
    }
  }
}
```

**Bearer token example:**

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": ["--yes", "@daxiong888/mcp-jenkins@latest"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com",
        "MCP_JENKINS_BEARER_TOKEN": "your_bearer_token"
      }
    }
  }
}
```

**Multiple Jenkins instances:**

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": ["--yes", "@daxiong888/mcp-jenkins@latest"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com,https://scheduler.yourcompany.com",
        "MCP_JENKINS_USER": "your_username,your_username",
        "MCP_JENKINS_API_TOKEN": "token1,token2"
      }
    }
  }
}
```

### 3. Restart

Quit (Cmd+Q / Alt+F4) and reopen Claude Desktop.

## 💻 GitHub Copilot CLI

**For:** New GitHub Copilot CLI (`@github/copilot`) in your terminal

**Note:** This is for the NEW Copilot CLI (`npm install -g @github/copilot`), not the old `gh copilot` extension.

### Option 1: Config File with Env Vars (Recommended)

Create or edit `~/.copilot/mcp-config.json`:

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": ["--yes", "@daxiong888/mcp-jenkins@latest"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com",
        "MCP_JENKINS_USER": "your_username",
        "MCP_JENKINS_API_TOKEN": "your_api_token"
      }
    }
  }
}
```

Then run: `copilot`

### Option 2: Config File with a CLI URL Arg

Credentials stay in `env`; only the non-secret URL is passed as an argument:

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": [
        "--yes",
        "@daxiong888/mcp-jenkins@latest",
        "--url",
        "https://pipeline.yourcompany.com"
      ],
      "env": {
        "MCP_JENKINS_USER": "your_username",
        "MCP_JENKINS_API_TOKEN": "your_api_token"
      }
    }
  }
}
```

### Option 3: Config File Reference

Save the config to a file and reference it (an inline `--additional-mcp-config '{...}'` would land the whole JSON — credentials included — in your shell history):

```bash
# Save config to jenkins-mcp.json (keep it out of version control)
copilot --additional-mcp-config @jenkins-mcp.json
```

For local installation, use `"command": "node"` with the path in args and credentials in `env`:

```json
"args": ["/absolute/path/to/mcp-jenkins/dist/index.js"],
"env": { "MCP_JENKINS_URL": "...", "MCP_JENKINS_USER": "...", "MCP_JENKINS_API_TOKEN": "..." }
```

### Option 4: Multiple Jenkins instances

```json
{
  "mcpServers": {
    "jenkins": {
      "command": "npx",
      "args": ["--yes", "@daxiong888/mcp-jenkins@latest"],
      "env": {
        "MCP_JENKINS_URL": "https://pipeline.yourcompany.com,https://scheduler.yourcompany.com",
        "MCP_JENKINS_USER": "your_username,your_username",
        "MCP_JENKINS_API_TOKEN": "token1,token2"
      }
    }
  }
}
```

### Option 5: Allow All Tools (Non-Interactive)

For scripts and automation:

```bash
copilot --allow-all-tools -p "Check status of mobile-pipeline build"
```

## 🔧 All JetBrains IDEs

**For:** IntelliJ IDEA, WebStorm, PyCharm, GoLand, RubyMine, PhpStorm, Rider, CLion, DataGrip

Settings (Cmd+, / Ctrl+,) → **Tools** → **AI Assistant** → **Model Context Protocol** → Add Server:

- **Name:** Jenkins
- **Command:** `npx`
- **Arguments:** `--yes @daxiong888/mcp-jenkins@latest`
- **Environment Variables:**
  ```
  MCP_JENKINS_URL=https://pipeline.yourcompany.com
  MCP_JENKINS_USER=your_username
  MCP_JENKINS_API_TOKEN=your_api_token
  ```

**Multiple Jenkins instances:** set these environment variables:

```
MCP_JENKINS_URL=https://pipeline.yourcompany.com,https://scheduler.yourcompany.com
MCP_JENKINS_USER=your_username,your_username
MCP_JENKINS_API_TOKEN=token1,token2
```

For local installation, use **Command:** `node` and **Arguments:** `/absolute/path/to/mcp-jenkins/dist/index.js`

Apply and restart the IDE.

**Alternative:** If MCP isn't available, use an MCP-compatible CLI from the built-in terminal (Alt+F12 / ⌥F12)

**Notes:**

- Ultimate/Professional editions: Full AI Assistant MCP support
- Community editions: Use an MCP-compatible CLI from the terminal instead
